# KNode V3 — 项目数据格式

本文件按本轮用户确认更新。V3 为唯一支持格式，取代历史阶段文档中的 V1/V2 结构约定。
不编写迁移器，不读取旧布局字段。版本不支持、JSON 损坏或校验失败时拒绝打开/保存，不改写原文件。

## 项目结构

根字段恰为：

- format: "forest-project"：保留现有签名。
- version: 3：唯一版本字段，不再使用 schemaVersion。
- projectId：稳定 UUID；重命名不改变。
- name：项目名称。
- nodes：全项目唯一的真实节点数组。
- views：恰含 tree 与 graph。

完整可执行样例见 [tests/fixtures/project-v3.json](../../../tests/fixtures/project-v3.json)，由 TypeScript 与 Rust 测试共用。

## 节点与视图

节点字段：id、title、parentId、progress、weight、color，以及可选 linkedPaths。

节点 `id` 必须为 1–128 个 ASCII 字符，只允许英文字母、数字、下划线 `_` 和连字符 `-`，并且须避开 Windows 保留名称，例如 `CON`、`NUL` 或 `COM1`。节点 ID 在整个项目中忽略大小写后唯一。
`progress` 始终保存手动值，必须是 0–100（含端点）的有限数，可以有小数。`weight` 为非负安全整数。存在正权重孩子时有效进度按孩子递归加权，否则回退自身手动值。自身权重只影响向父节点的贡献及进度条显示。
color 保存节点独立的六位 HEX，新建节点默认为 `#6c9661`。旧 V3 的 null 仍可读取，打开时按原来可见的颜色在内存中补齐，随下次保存写入。
节点不存 position、collapsed、documents、内部文件清单、计算进度或 Vue Flow 运行时字段。

tree 恰含：

- positions：节点 ID 到 { x, y } 的映射，必须覆盖所有真实节点，不能含未知 ID。
- collapsedIds：不重复的真实节点 ID 数组，仅控制树中后代的可见性。
- viewport：{ x, y, zoom }。

graph 恰含：

- positions：节点 ID 到 { x, y } 的映射；映射的键就是加入图的节点集合，允许为空或只含部分节点。
- edges：{ id, source, target, direction, label? } 数组。端点必须都加入图。边 `id` 与节点 ID 使用相同的字符、长度及 Windows 名称规则，在 `graph.edges` 内按原始字符串区分大小写，且必须唯一。
- viewport：{ x, y, zoom }。

direction 只允许 forward、both、undirected。允许自环、循环、多入边、多出边和平行边。
label 为可选的非空文本（1–200 字符），不接受 null。
两套 positions/viewport 各自持久化，不互相覆盖；不保存当前活动视图。
坐标为有限数且绝对值不超过 1e9，zoom 范围 0.2–2.5。所有对象拒绝未知字段。

## 操作语义

- parentId 仍只定义森林：可多根、每节点至多一个父节点、禁止树自环及树循环。
- 图边不参与树进度和 parentId 计算。树与图共用节点自身的颜色。
- 在树中新建真实节点时，同时建立树和图的坐标。图中不自动创建连线。
- 图中新建真实节点，在树中作为根，并分别建立两套坐标。
- 两种视图共用全部真实节点。图中没有单独移出节点的命令。
- 读取旧 V3 项目时，保留原有 Graph 坐标、连线和视口，为缺少图坐标的节点补位。打开时先补到内存，下次手动保存或编辑自动保存时一并落盘。
- 真实节点删除时清理两套视图的引用；内部文件仍按现有规则保留，撤销可恢复。
- 撤销按命令记录节点业务字段、两套布局、树折叠和图边；两套视口导航均不回退，默认上限 100。
- 树复制保留明确选区内树关系；图复制生成真实根与新图布局，仅重映射选区内图边，不改变原图。

## 磁盘与 I/O

沿用“项目目录/同名 JSON”；内部文件按需放入 Nodes/<节点ID>/，不写入 JSON 清单。

桌面端读取或保存项目 JSON 时，上限为 32 MiB（33,554,432 字节）。读取按磁盘上的文件字节数计算，保存按 UTF-8 JSON 的字节数计算。
外部文件通过 `linkedPaths` 引用，不因视图编辑而移动、复制或删除原件。没有外部关联时省略 `linkedPaths`。填写时须为非空字符串数组，并遵守以下规则。

- 每条路径须为 1–4,096 个 UTF-16 代码单元。支持相对于项目目录的路径、带盘符的绝对路径（如 `D:/资料/说明.md`）和含服务器及共享名的 UNC 路径（如 `//server/share/说明.md`）。`/` 和 `\` 均可作分隔符。仅盘符后的冒号可用于绝对路径，`D:说明.md` 或 `/说明.md` 这样的写法会被拒绝。
- 除 `.` 和 `..` 外，每个路径组成部分须符合 Windows 文件名校验，上限为 240 个 UTF-16 代码单元。校验拒绝空组成部分、末尾的点或空格、控制字符、非法字符（如 `<>:"|?*`）及 Windows 保留名称。
- 同一个节点内不能重复关联规范化后相同的路径。判重时统一分隔符、忽略大小写、略过 `.` 并在可折叠时消去 `目录/..`。通过界面添加或重新定位时，Rust 还会对指向同一个实际文件系统目标的路径去重。
所有项目创建、打开、保存、重命名和文件接口都通过同一 Rust V3 验证器。
前端解析、导出 JSON、自动保存、关闭前保存统一通过 V3 类型/验证器。
保持原有串行自动保存、临时文件同步后替换、外部更改检查和文件目录安全保护。

标题栏在打开项目后提供树、图两个图标按钮。App 与 ForestCanvas 共用同一视图控制器，默认 tree。切换不产生历史记录，当前活动视图不写入 JSON。
历史规格及阶段报告仅作开发记录，不应再用它们的旧 JSON 示例创建当前项目。

## 按需自动整理

自动整理只通过现有 moveViewNodes 更新当前视图的 positions，不改节点业务字段、parentId、edges 或 collapsedIds；一次应用对应一条历史。树中隐藏的后代不参与布局，其原坐标保留。自动适配视野复用现有画布导航，不增加布局历史。方向偏好按树/图分开存于应用 localStorage 的 knode-layout-directions，不进入项目 JSON。
